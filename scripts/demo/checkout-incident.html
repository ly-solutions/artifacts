Checkout latency incident, 14 March

For 38 minutes, checkout requests in the EU region took up to 9 seconds and 4% of them failed. The cause was a connection pool that the new payment client never released after a timeout. This review covers what happened, why our alerts were late, and what changed.

Root cause

The client acquired a connection before the request deadline was checked. On timeout the error path returned early and skipped release(), so every timeout leaked one connection until the pool of 64 was exhausted.

conn := pool.Acquire(ctx)
if err := ctx.Err(); err != nil {
    return err // leaked: conn is never released
}
defer conn.Release()

What we changed

  • Release is deferred right after acquire, and a lint rule flags the old pattern.
  • Pool saturation alerts at 80% for two minutes, before latency moves.
  • Payment client rollouts go 5% → 25% → 100% with a ten-minute hold.
Detection, not the bug, made this an incident: the pool was saturated for nine minutes before any alert looked at it.
